## 1. Intent

WSurf is a native macOS browser (macOS 26+, EXISTING: WebKit default, Chromium on demand per site, spaces/profiles, address-bar assistant, MCP server off by default). Flux is the brand idea of *adapting to the user*: a switch/track whose knob flows into a second shape. One mark, six selectable palettes, light and dark sets, plain and textured finish.

Positioning (DESIGN): primary tagline **"A browser that adapts to you."**
Alternates: "Your browser, shaped your way." / "One browser. Every way you work." / "Browse your way. Build your way."
Voice: plain, concrete, no hype. Banned claims unless separately proven: magic, unlimited, private, secure, fastest, lighter on RAM, "download now" (website says "In development"; no verified public signed release). Call to action until a release exists: **"See the source on GitHub"** (github.com/wsagency/wsurf).

## 2. Mark (DESIGN, geometry EXISTING in `assets/mark.svg`)

- Master: viewBox 1024, drawn bbox x 40-984, y 202-822 (944 x 620, aspect 1.523:1). Two shapes: **track** (evenodd stadium with a pill-with-bridge cut-out) and **knob** (gourd). The gap between them is *transparent*, so the surface shows through as the ring. Never fill the gap.
- Gradients: track from deep to bright along (40,202)->(984,822); knob start to end along (260,512)->(860,512).
- Small geometry (`assets/mark-small.svg`, bbox 32-992 x 182-842): heavier ring, bigger gap, **flat two-colour** (track deep + knob start), no gradient. Use for any render narrower than 64 px.
- Optical centre: measured alpha centroid of the master is x 498.8, y 511.5 vs bbox centre 512,512, i.e. 13.2 of 944 units (1.4%) left. Centre by bbox; revisit only in the Dock spike.
- Clear space **x = 1/4 of the mark width** on every side, also around the lockup (x from the mark width, not the lockup width). Minimum: mark 16 px (small geometry), lockup 96 px wide.
- Not allowed: recolouring outside the palettes, outlining, gradients on small geometry, texture on <= 64 px, stretching, drop shadows baked into the file, filling the ring.

## 3. Wordmark and lockup

- Wordmark = "WSurf" set in **Figtree Bold**, converted to outlines (`assets/wordmark.svg`). Kerning from the font's GPOS via HarfBuzz, tracking +10/1000 em. Ink `currentColor`.
- Lockup (`assets/lockup.svg`): mark at scale 0.2 (188.8 x 124), wordmark cap height = 0.62 x mark height (76.9), gap = 0.22 x mark width (41.5), caps centred vertically on the mark, viewBox 556.75 x 124.
- Ink on light `#1D1D1F`, on dark `#F5F5F7`. Mono lockup: one ink via `currentColor`.
- UI text stays the system font (SF). Figtree is used only in the outlined logo, so no web-font hosting is needed for the brand.
- The hand-drawn lettering in the earlier concept lockup (`docs/logo-concepts/c-opus-5-5/...-lockup.svg`, untracked, not in this branch) is **not used**.

## 5. Mono

One ink, `currentColor`, ring left transparent: `exports/mono/mark-mono.svg`, `lockup-mono.svg`. Positive = dark ink on light, reverse = light ink on dark, or white / dark-brand ink on a Flux surface (see `specimen.png` section 5). Use mono when the surface is a photo, a one-colour print, or a system template image.

## 6. Texture (DESIGN)

Optional **textured finish** for raster art >= 128 px only (Dock tile, social/OG, large web art). Never on favicons, tabs, UI, mono, or any render < 128 px.
Filter (`GRAIN` in `tools/gen.py`, deterministic): `feTurbulence type=fractalNoise baseFrequency=0.85 numOctaves=2 seed=7`; light grain alpha = `3.2R - 1.85`, dark grain alpha = `-3.2R + 1.35`, each clipped to the mark's alpha and scaled x0.22, merged over the mark. Specified in master (1024) units. Bake to PNG at export so output is identical everywhere; do not ship the live filter to the app.

## 8. In-app Dock icon (DESIGN; no code written)

### 8.1 Product contract
- Row "Dock icon" in Settings > Appearance, near the Theme card. Choice = palette (6) x finish (Smooth/Textured). Default = **Flux / Smooth**, which sets `NSApp.applicationIconImage = nil` so the native bundle icon (and its system light/dark/tint rendering) is used.
- Helper text, **final wording gated on the probe in 8.3**: draft "Changes the icon shown in the Dock while WSurf is running." Only add "Finder and Launchpad keep the standard WSurf icon" if the probe confirms it. Do not say "app icon".
- Settings keys (follow `BrowserSettings` `Key`/`globalValue`/`setGlobal`, app-global, not in `sessionKeys`): `appearance.appIconPalette`, `appearance.appIconFinish`. Reset in `resetToDefaults()`. Apply in `BrowserApplication.bootstrap` right after `applyAppearance()`, and on change. Settings index entry + `Localizable.xcstrings` + tests for each new anchor.
- Independent of the integration branch's `ThemePreset` (`a98f51f`, not merged; touches the same Settings files): build the row as its own file and rebase after the merge.
- Selection follows the effective appearance (light/dark PNG) at apply time; whether to observe live appearance changes is open (8.3).

### 8.2 Platform limits (stated up front)
- **EXISTING (docs)**: `NSApplication.applicationIconImage` changes the Dock tile only, temporarily; `nil` restores. macOS has no alternate-icon API (`setAlternateIconName` is UIKit/Catalyst).
- Dock tile for a not-running or pinned app, Finder, Launchpad: expected to remain the bundle icon. **UNVERIFIED.**
- Cmd-Tab, Mission Control, notifications, About/alert boxes, Sparkle: **UNKNOWN** whether they follow `applicationIconImage` or the bundle icon. Not promised, not denied until probed.
- No bundle writes, no `NSWorkspace.setIcon` on the installed app, no hand-edited `Info.plist` icon keys, no entitlement/profile change. The runtime property needs no new capability. Newly bundled image files are a normal rebuild + re-sign + notarize.
- Existing readers of `NSApp.applicationIconImage` (About `SettingsView.swift:305`, onboarding `OnboardingIntro.swift:51`, `OnboardingScreens.swift:376`) do not observe changes; decide whether they show the chosen or the default icon.

### 8.3 Runtime probe (required before any claim; not run)
On a built Debug/Stage app (never the installed signed app), on the existing Pro Xcode 27 verification host; do **not** install Xcode 26.5:
1. Set a candidate PNG live; check masking/size/shadow (does macOS add its own mask or expect pre-masked art), dark/tinted/clear Dock icon styles, `nil` restore.
2. Quit and relaunch: flash of default icon, pinned tile when not running, minimised-window tiles.
3. Cmd-Tab, Mission Control, notification, About, alert, Sparkle; Finder/Launchpad unchanged.
4. Whether an extra `.icon` can be loaded via `NSImage(named:)`, or PNGs must ship (current plan).
5. actool output keys in the built `Info.plist`; `codesign --verify --deep --strict`.
6. Stage isolation: the key is saved in the stage defaults suite only.
If masking or tint make the images look wrong, fallback: ship only flat fill choices via `.icon` fill-specializations (also UNVERIFIED) or drop the picker and keep Flux only.

## 10. Acceptance criteria (testable)

- Every palette: track deep and track bright >= 3:1 on the intended surface (values in section 4); knob start >= 1.6:1 on light, >= 9:1 on dark.
- Mark renders legibly (ring visible, knob distinct) at 16/32/48 px with small geometry on both surfaces (`specimen.png` section 3).
- `exports/` SVGs contain no live `feTurbulence` (grain exists only baked into Dock PNGs and in `specimen.svg`) and only the favicon SVGs use CSS variables (for the dark-mode media query); textured PNGs are visually identical across reruns of `tools/gen.py` (pixel determinism across machines UNVERIFIED).
- Each wired surface uses only files from `exports/`; no hand-copied path data (the DMG script is migrated).
- Dock picker: choice persists across relaunch; default restores the native icon; helper copy matches 8.3 probe results.
