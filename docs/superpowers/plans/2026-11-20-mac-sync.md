# iCloud sync on Studio and Air

Implement from the [Mac sync design](../specs/2026-11-20-mac-iphone-sync-design.md). Use Superpowers test-driven development for each part and independent review before merge. The sync candidate is 0.2.0 (build 32), following the signed 0.1.31 patch.

## Delivery

| Part | Production entry points | Acceptance on two Macs |
| --- | --- | --- |
| Shared Spaces, tabs and pins | WSurfCore sync records and router, CloudSync, SpaceStore, ProfilePinStore, BrowserModel and Settings → Sync | Studio publishes a Space. Air joins from a populated profile. Opening, moving, closing, reordering and favoriting tabs converge. Each Mac retains its local Spaces and active tab. Two tabs with the same URL remain distinct. |
| Website settings and assistant providers | SitePermissions, ContentBlocker, ProviderCatalog, per-profile model settings and Settings → Sync | Each category defaults off. Explicit changes and resets reach a participating Mac at the original origin, host, site or profile scope. Sensitive grants request consent on the receiving Mac. |
| Saved provider keys | CredentialStore, a separately enabled encrypted key channel, and individual provider endpoint approval | A synthetic saved key works on the approved endpoint on the receiving Mac. A changed endpoint requires confirmation. Environment variables, OAuth tokens and MCP credentials remain device-local. |
| Complete credential vaults | VaultSync, VaultSyncCodec, attachment storage, the existing credential settings model and per-vault opt-ins | Two different populated vaults coexist. A disposable synced vault can be added with its passkey. Files and file-only entries survive interrupted transfer. Referenced revision and Trash assets remain recoverable under the existing local purge policy. |
| Settings and delivery | SettingsNavigation, SettingsView, Settings search, signed Development archive and the two-Mac trial | Users can reach the category switches directly on each Mac, see availability, and pause sharing. The signed trial uses a disposable Space, vault, website rule and provider fixture. |

## Checks

- [ ] Establish the exact expected differences with two populated FakeSyncCloud clients before implementing each category. Repeat with an initially offline client and a Mac joining after the first upload.
- [ ] Implement opt-in through each existing Mac store. Persist mappings, pending writes and deletion markers before sending. Fetch a baseline before enabling writes. Keep the active window and private browsing state on that Mac.
- [ ] Reopen both stores and replay interrupted changes. Test a remote account switch with queued writes, local-only edits, concurrent close/move and deletion versus a stale edit. Only fresh consent can publish into another account.
- [ ] Verify website permission scope, per-endpoint key consent, vault passkey protection and encrypted attachments with synthetic data. Check that personal secrets are absent from configuration records and logs.
- [ ] Run targeted native tests under the Pro lock, then the complete minor validation on the feature and merged commit, including memory and performance. Sign and install the verified candidate on Studio and Air. Use a disposable feature record for the automated iCloud round trip. Verify the controls end to end in separate signed-in macOS test users when those logins are available.
